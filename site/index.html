Agent integrations

six mechanisms that run · each one says what it prevents

01

Agent-to-agent handoff

One agent passes a piece of work to another through a call that carries its own context and its own chat, so the receiving agent starts with the whole brief and answers in the same thread, not in a fresh blank session.

Preventswork arriving as a bare sentence with the reasoning stripped off.

02

Missions

A multi-ticket job runs inside one worktree, in its own turns, for as long as it takes, instead of one ticket per invocation.

Preventsa long job dying halfway with its state only in a chat log.

03

Scheduled cron jobs

A job runs on a schedule and speaks only when something is wrong.

Preventsa silent failure being found by a person weeks later.

04

Delegation to a coding agent in its own terminal pane

Code is written by a coding agent with its own session and its own working tree, briefed by a lead that routes and verifies.

Preventstwo agents editing one file, and a claim of “done” going unchecked.

05

The review gate

Every pull request is reviewed by a reviewer agent on the exact commit, findings go back to the authoring agent, fixes are batched into one commit per round, and nothing merges until the gate is satisfied.

Preventsan unreviewed change reaching a deployed service.

06

One owner per thing

Each piece of work is assigned to exactly one agent and one branch.

Preventsa merge conflict discovered at merge time.

Every crossing is explicit: who may read, who may write, who must ask. A handoff carries its own context, so the receiving agent starts with the full brief instead of guessing. Work stops at the gate, and a person makes the final call. Each box names an actor or artifact; the logs stay elsewhere.
