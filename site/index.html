Agent infrastructure

six mechanisms in use, each with the failure it prevents

01

Agent-to-agent handoff

One agent passes work to another through a call that carries its own context and chat. The receiving agent starts with the whole brief and replies in the same thread, not in a blank session.

Preventswork arriving as a bare sentence with the reasoning stripped off.

02

Missions

A multi-ticket job runs inside one worktree, in its own turns, for as long as it takes, instead of one ticket per invocation.

Preventsa long job dying halfway with its state only in a chat log.

03

Scheduled cron jobs

A job runs on a schedule and speaks only when something is wrong.

Preventsa silent failure being found by a person weeks later.

04

Delegation to a coding agent

Code is written by a coding agent in its own session and working tree. A lead agent briefs it, routes the work and verifies the result.

Preventstwo agents editing one file, and a claim of “done” going unchecked.

05

The review gate

A reviewer agent reviews every pull request on the exact commit. Findings go back to the authoring agent, fixes land as one commit per round, and nothing merges until the gate passes.

Preventsan unreviewed change reaching a deployed service.

06

One owner per task

Each task is assigned to exactly one agent and one branch.

Preventsa merge conflict discovered at merge time.

Each path ends at something that checks or someone who decides. A handoff carries its own context, a change stops at the review gate, a scheduled job reports only failures, and a deploy does not start without a person saying so.
